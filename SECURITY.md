# Forge Security Policy

Forge is an offensive security validation platform for authorized testing only.

## Authorization Requirement

- You must have explicit written authorization before testing a target.
- You must follow the target scope, rules of engagement, and legal boundaries.
- Unauthorized testing is prohibited.

## Responsible Disclosure

- Report discovered vulnerabilities privately to system owners first.
- Provide clear reproduction steps, impact, and remediation guidance.
- Do not publish exploit details until owners have had reasonable time to remediate.

## Safe Usage Policy

- Use Forge only in approved environments and approved scopes.
- Avoid production-impacting payloads unless explicitly allowed.
- Respect rate limits, maintenance windows, and data handling restrictions.
- Do not use Forge for persistence, data theft, or destructive actions.

## Data Handling

- Findings may include sensitive evidence (requests, responses, tokens, screenshots).
- Store evidence securely and limit access to authorized personnel.
- Remove or redact secrets before sharing reports externally.

## Reporting Security Issues in Forge

If you find a security issue in Forge itself, open a private security report via the repository security contact process.
